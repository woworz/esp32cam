# ESP32 端原理

## 客户端模式

ESP32 位于普通局域网/NAT 后，公网服务器通常无法直接访问它。因此设备不再提供业务 HTTP 服务，而是主动发起出站请求：

```text
ESP32 ──GET 命令──► 公网服务器
ESP32 ──POST 图片─► 公网服务器
ESP32 ──POST 结果─► 公网服务器
```

该模式不要求路由器端口映射，也不会让摄像头实时流直接暴露在局域网或公网。

## 启动与配网

1. `boot.py` 加载 `/wifi_config.json` 并连接 WiFi。
2. 连接失败时临时开启 `ESP32-CAM-Config` AP。
3. 用户访问 `192.168.4.1` 保存 WiFi。
4. 设备重启，连接成功后关闭 AP 并进入客户端主循环。

保留配网服务器是为了设备换网络时仍可恢复，不代表板载业务网页仍存在。

## 单线程事件循环

旧版本为 HTTP 主线程、按键线程、拍照线程及 MJPEG 访问共享摄像头。新版本改为单线程循环，避免摄像头竞争、线程栈占用和长连接内存压力。

循环同时处理：

- GPIO21 下降沿与 300ms 消抖；
- 每 2 秒命令轮询；
- WiFi 断线重连；
- 拍照、TFT 显示、上传；
- 命令结果回报。

## 命令可靠性

设备领取命令后，服务器将状态置为 `processing`。上传成功后设备回报 `completed`，否则回报 `failed`。如果领取后设备断电且未回报，服务器在 60 秒后允许重新领取。

## 图片上传

设备使用 `multipart/form-data` 上传：

- `image`：JPEG 二进制；
- `text`：叠加文字；
- `device_id`：设备标识。

响应对象始终在 `finally` 中关闭，并在网络操作后执行 `gc.collect()`，减少 MicroPython 堆碎片。

## 摄像头与屏幕

- OV3660 使用 DVP、20MHz XCLK、JPEG 和 PSRAM 帧缓冲。
- 默认 VGA、质量 12，兼顾文件大小与清晰度。
- ST7789 使用 SPI1@20MHz，拍照后显示图像；无 JPEG 解码库时显示文字状态。
